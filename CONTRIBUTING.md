# Правила работы с репозиторием

## Именование веток

Формат для **студентов**:

```
[тип]-[ФИО студента]-[курс]-[название-задачи]
```

Формат для **преподавателя** (номер курса не указывается):

```
[тип]-[ФИО преподавателя]-[название-задачи]
```

- **тип:** `feat` / `fix` / `chore` / `docs` / `test` / `refactor` и т.п.
- **ФИО автора:** транслитом, `ivanov-ii` (или `bahmackiy-vi` для преподавателя).
- **курс:** номер группы/курса, например `к3и1` — только для студентов.
- **название задачи:** короткий слаг через дефисы.

Примеры:

```
feat-ivanov-ii-к3и1-virtio-blk-driver        (студент)
fix-petrov-an-к3и1-kmalloc-oob               (студент)
docs-bahmackiy-vi-update-lecture-plan        (преподаватель)
```

## Формат коммитов

Первая строка:

```
[тип]: краткий текст коммита
```

Далее пустая строка и список того, что сделано:

```
[feat]: драйвер virtio-blk

- Добавлен инициализация virtio-очереди
- Реализовано чтение секторов через read()
- Добавлены smoke-тесты в scripts/test.sh
```

```
[fix]: выход за границы в kmalloc

- Исправлен расчёт размера блока при выравнивании
- Добавлен проверочный тест на аллокацию 0 байт
```

## Pre-commit проверки

Каждый коммит автоматически прогоняется pre-commit-скриптами — закоммитить код,
который ломает сборку или тесты, невозможно.

Что проверяется перед каждым коммитом:

1. Сборка (`scripts/build.sh`) — код должен компилироваться.
2. Smoke-тесты (`scripts/test.sh`) — ОС должна грузиться в headless QEMU
   и проходить базовые сценарии.
3. Форматирование/линт — единый стиль кода.

Установка хуков в локальный клон:

```bash
git config core.hooksPath .githooks
```

Хук лежит в `.githooks/pre-commit` и запускает все проверки. Если проверки
не прошли — коммит отменяется, чините и пробуете снова. Обойти хук
(`--no-verify`) студентам запрещено; на ревью это видно сразу.
