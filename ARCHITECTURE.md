# Скелет операционной системы

Целевая платформа: x86_64, загрузка в QEMU (UEFI через Limine). Цель — не «ещё один Linux»,
а минимальное, но честное ядро: свои syscalls, свои процессы, своя ФС, свой userland.

## Слои системы (снизу вверх)

```
┌─────────────────────────────────────────────┐
│ Self-hosting: свой компилятор C, make,      │  слой 7 — дальняя цель
│ портирование bash/zsh, CPython              │
├─────────────────────────────────────────────┤
│ GUI (TUI / immediate-mode / тайловый WM)    │  слой 6 — конкурс групп
├─────────────────────────────────────────────┤
│ Userland: libc, shell (msh), coreutils      │  слой 5
├─────────────────────────────────────────────┤
│ ELF-загрузчик, ring 3, пользовательские     │  слой 4
│ процессы                                   │
├─────────────────────────────────────────────┤
│ VFS, файловая система, пайпы                │  слой 3
├─────────────────────────────────────────────┤
│ Слой syscall, планировщик, контекст-свитч,  │  слой 2
│ менеджер памяти ядра                        │
├─────────────────────────────────────────────┤
│ Драйверы: tty, клавиатура, таймер,          │  слой 1
│ virtio-blk, serial                          │
├─────────────────────────────────────────────┤
│ Boot (Limine) + раннее ядро: GDT/IDT,       │  слой 0
│ пейджинг, kmalloc                           │
└─────────────────────────────────────────────┘
```

## Компоненты и порядок реализации

### 0. Загрузка и раннее ядро
- **Bootloader: Limine.** Не пишем свой — он даёт карту памяти, framebuffer и вход
  сразу в long mode. Свой бутлоадер — возможная тема «со звёздочкой».
- **GDT/TSS** — сегментация (наследие) + стек для прерываний ring 3.
- **IDT + ISR-трамплины** — прерывания и исключения; panic handler с дампом регистров.
- **Serial-вывод (COM1) с самого начала** — главный канал логов и для нас, и для ИИ-агента.
- *Критерий готовности:* ядро грузится, печатает в serial и на экран, ловит page fault
  с понятным сообщением.

### 1. Драйверы (базовый набор)
- **Клавиатура** (PS/2 через IRQ1) — ввод для будущего shell.
- **Таймер** (PIT → локальный APIC) — тики для вытесняющей многозадачности.
- **virtio-blk** — блочное устройство в QEMU: простое и документированное.
- Модель драйвера минимальная: таблица драйверов + `init()/read()/write()`-интерфейс.
- *Критерий готовности:* читаем сектора с диска-образа по прерыванию от клавиатуры.

### 2. Память и многозадачность ядра
- **PMM** — аллокатор физических фреймов (bitmap, позже бадди), питается картой Limine.
- **VMM** — свои таблицы страниц, higher-half ядро, map/unmap, позже COW и cow-fork.
- **kmalloc/kfree** — куча ядра (free-list / slab).
- **Задача (task):** struct с сохранёнными регистрами, стек, состояние.
- **Контекст-свитч** на ассемблере; **планировщик** — кооперативный → round-robin → приоритеты.
- **Ядерные потоки (kthreads)** — сначала многозадачность без пользователей, для отладки.
- *Критерий готовности:* несколько kthreads переключаются по таймеру, печатают в serial.

### 3. Файловая система и VFS
- **VFS:** inode-интерфейс, таблица дескрипторов процесса, пайпы.
- **ФС:** FAT32 (проще) или ext2-подобная (интереснее) на диске-образе, собираем
  утилитой на хосте (mkfs-скрипт).
- **initrd** — стартовый ramdisk для раннего userland, пока нет блочного драйвера.
- *Критерий готовности:* ядро читает файл с образа, пайп работает между задачами ядра.

### 4. Пользовательский режим
- **Механизм syscall:** `syscall`/`sysret` (или int 0x80 для простоты), ABI-документ
  в markdown — он же «промпт» для агентов и студентов.
- **Минимальный набор:** exit, read, write, open, close, fork (через COW), execve, waitpid, mmap.
- **ELF-загрузчик** в ядре; создание адресного пространства пользователя, ring 3,
  обработка user page fault.
- *Критерий готовности:* ELF из образа запускается в ring 3, делает write в serial,
  fork работает.

### 5. libc и userland
- **Мини-libc** (freestanding): строковые, malloc (free-list), stdio поверх syscall'ов,
  стартовый код `crt0`, собственный linker-script.
- **`msh`** — эталонный shell от лектора + **конкурс версий** между группами:
  job control (процессные группы, `fg`/`bg`/`&`), автодополнение и история,
  скриптовый язык (переменные, `if`/`for`, функции). Победитель — шелл по умолчанию.
- **coreutils:** cat, ls, echo, ps, free и т.п. — идеальные задачи для делегирования агентам.
- *Критерий готовности:* shell принимает команды, пайпы работают в userland.

### 6. Графика
- Framebuffer (получен от Limine) → шрифт → примитивы → оконная модель.
- Конкурс реализаций: TUI-композитор / immediate-mode GUI / тайловый WM.
- Мышь (PS/2 или virtio-input).

### 7. Self-hosting и экосистема (дальняя цель)
- **Self-hosted компилятор C:** маленький C11-компилятор (подход chibicc) или портированный
  tcc, собираемый и работающий **на самой ОС**. Требует: ФС с записью, достаточно
  полный набор syscall'ов (mmap, fstat, …), libc с stdio/файлами.
- Веха self-hosting: ОС компилирует hello.c на своей ФС и запускает результат —
  без хост-машины. После этого портирование тулинга становится механической работой.
- **Порядок экспансии экосистемы:** make → binutils (ar, ld — если свой линкер не в ядре)
  → **bash** (нужны: pty, signals, job control) → **zsh** → **CPython**
  (нужны: mmap, fork/exec, poll/select, socket'ы или их заглушки, dlopen или статика).
- Каждый этап портирования — отличная задача для ИИ-агентов: много рутины
  (конфиги, #ifdef, заглушки), но нужен контроль со стороны человека.

## Структура репозитория (цель)

```
os/
├── kernel/          # ядро: boot, mm, sched, fs, drivers, sys
├── libs/            # мини-libc, libgfx и пр.
├── userland/        # msh, coreutils
├── toolchain/       # скрипты сборки кросс-тулчейна
├── scripts/         # run.sh, test.sh, debug.sh, mkfs
├── docs/            # ABI syscalls, конвенции кода — «документация как промпт»
└── AGENTS.md        # правила для ИИ-агентов, работающих над репозиторием
```

## Правила вайбкодинга для этого репозитория
1. Любое изменение ядра проверяется прогоном `scripts/test.sh` — агент обязан его вызывать.
2. Каждый новый syscall сначала описывается в `docs/syscalls.md`, потом реализуется.
3. Все логи — в serial: агент читает их из файла и сам понимает, что сломалось.
4. Панрика недопустима молчаливая: panic обязан печатать контекст в serial.
